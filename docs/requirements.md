## 제출 방식

원문은 GitHub Repository 링크로 제출하도록 명시합니다. 코드·Dockerfile·기술 문서·로그·증거를 저장소에서 확인할 수 있어야 합니다. 파일을 나누어도 README의 링크로 접근할 수 있어야 합니다. 공개 저장소 또는 과제 제출 규칙에 맞는 접근 권한을 사용합니다.

## 실행과 증거

- 작업은 CLI 기반으로 수행하고 Dockerfile을 작성합니다.
- 파일 1개와 디렉터리 1개 이상의 권한 변경 전후를 기록합니다.
- Docker 버전·엔진·이미지·컨테이너·로그·리소스와 hello-world·Ubuntu 실행을 확인합니다.
- 선택한 기본 이미지와 커스텀 목적, build/run 결과를 적습니다.
- 포트 매핑, 바인드 마운트 전후, 볼륨의 컨테이너 삭제 전후를 확인합니다.
- 기술 문서의 명령과 출력은 코드 블록으로 표시하고, 민감정보는 제외·마스킹합니다.
- Git 작성자·기본 브랜치와 GitHub·VS Code 연동 증거를 준비합니다.
- 실제 문제 해결 2건 이상을 문제·가설·확인·해결 순서로 적습니다.
- 다른 평가자가 README를 따라 확인할 수 있도록 절차와 개인 PC 경로 대안을 적습니다.

기능 요구사항에는 curl 응답을 접속 증거로 허용하는 문장이 있고, 별도 제약에는 주소창과 포트를 포함한 브라우저 화면 규칙도 있습니다. 현재 curl 로그와 실제 화면, Chrome 원본 캡처의 주소창 localhost:18080 및 WORKSHOP_V1을 함께 확보했습니다. [주소창 포함 증거](../evidence/screenshots/chrome-addressbar-18080.png)를 확인할 수 있습니다.

## 참고 예시와의 구분

원문은 결과 예시를 그대로 제출하지 않도록 명시합니다. 이 프로젝트는 자체 HTML·CSS·JavaScript·NGINX 설정을 작성했습니다. NGINX는 80에서 수신하므로 예시 속 5000을 그대로 사용하지 않았습니다. 서울 캠퍼스용 OrbStack 설명은 경남 Windows WSL 환경의 설치 지시로 적용하지 않았습니다.

## 작성 및 검증 범위

2026-11-03 미션 상세 화면의 전체 요구사항과 제출 폴더를 대조했습니다. 터미널·권한·Docker·커스텀 이미지·포트·바인드 마운트·볼륨의 명령과 실제 출력, 문제 해결 2건, Git 설정, GitHub 업로드 및 VS Code 계정 화면을 준비했습니다. 코드 작성과 실행 검증에는 AI 도구를 활용했으며, 원문 로그의 실행 주체 표시는 `jarvis-assisted`로 보존했습니다. 기존 로그는 당시 실행 기록이므로 그 안의 업로드 전 상태를 사후에 바꾸지 않습니다.

Dockerfile 기반 커스텀 이미지의 빌드·실행, 포트 연결 후 HTTP 응답, 바인드 마운트 변경 전후, 볼륨의 컨테이너 삭제 전후 데이터 유지를 실제 로그로 확인했습니다. 원문의 직접 작성·설정·검증 조건과 여섯 과제 목표는 유지하며, 결과와 원리를 설명하는 학습 문서를 별도로 제공합니다. 코드·문서 작성과 실행 검증에 활용한 AI 도구의 지원 범위는 [작성 및 검증 범위](작성지원_및_검증범위.txt)에 정리했습니다.

## 선택 보너스

Compose 단일 서비스, 다중 서비스 및 통신, Compose 운영 명령, 환경 변수로 서버 포트·모드 변경, SSH 키를 이용한 push는 현재 제출자료에서 수행 증거를 제공하지 않습니다. 모두 선택 과제이며 필수 완료 항목에 포함하지 않습니다. 현재 HTTPS 방식의 GitHub 연결을 사용합니다.

## 남은 제출 절차

전용 저장소 업로드, VS Code GitHub 로그인·Ubuntu 프로젝트 연결 및 주소창 포함 접속 화면을 증거로 제공합니다. 2026-11-03 기준 저장소는 공개 상태입니다. 평가 시 코디세이에서 해당 저장소와 main 브랜치를 선택하고, 평가자의 접근 가능 여부를 확인합니다. 네이토 사전평가와 동료평가의 신청·완료 상태는 플랫폼에서 별도로 확인합니다.
